How to summarise a log file with Python

Short answer

A log file is a text record of what a program did, one line per event. When it grows long, a summary helps: how many lines of each level, which hours had errors, and which lines could not be understood. This lesson builds a small read-only Python tool that does that. It reads one log format only, and it shows you the lines it cannot read instead of hiding them.

Follow along and build it step by step. You add each file yourself, run each command, and see the real recorded result.

Common mistakes

  1. Skipping lines you do not understand. A summary that quietly ignores odd lines can hide the very lines that matter. This tool counts all of them, shows the first three with their line numbers, and says how many more there are.
  2. Trusting the hour as a real time zone. The hour is whatever the log wrote. This tool does not know which time zone that was.
  3. Treating the counts as the cause. Three ERROR lines tell you where to look. They do not tell you why they happened.
  4. Assuming every log looks the same. This tool expects a date, a time, an upper-case level and a message. Another format will mostly show as unreadable, which is the tool being honest, not the log being wrong.

Frequently asked questions

How do I summarise a log file with Python?

Read the file one line at a time, pick out the level on each line, and count them with collections.Counter. This lesson builds a small tool that does that and also counts errors per hour.

Will this change my log?

No. The tool only reads the file. A test checks that one small test file has the same bytes and modified time after a run. That is the only evidence for this claim.

What if my log has a different format?

Lines that do not match the expected format are all counted as unreadable. The first three are shown and the rest are reported as a number. You would change the parse step in the tool to match your format.

Why count unreadable lines?

So you can see how much of the file the summary really covered. A summary built on half the lines would look just as confident as one built on all of them.

Which Python features does it use?

collections.Counter for counting and datetime.strptime for checking that a timestamp is real, both from the official Python documentation.
